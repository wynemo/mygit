# MyGit → Rust + GPUI 迁移清单

以当前 Python 源码为功能基线，Rust 实现在 `gpui-prototype/` 中逐步推进。此清单按依赖和用户使用流程排序；完成每项后更新勾选状态并记录验证结果。旧版继续可用，待核心流程验收通过后再切换默认入口。

状态：`[x]` 已实现并验证；`[ ]` 待完成。原型已完成的部分单列，不能据此认定整个模块完成。P0 为日常使用前必需，P1 为现有功能补齐，P2 为发布与完善。

## 已完成的原型基线

- [x] B01 打开本地 Git 工作区、显示当前分支、手动刷新。
- [x] B02 显示当前 HEAD 最近 100 条提交，选中提交加载变更文件。
- [x] B03 获取工作区状态，包含暂存、未暂存、未跟踪文件。
- [x] B04 双栏只读 Diff：行号对齐、增删行底色、虚拟列表、同步垂直滚动及横向移动按钮。
- [x] B05 工作区按 HEAD ↔ 磁盘内容比较；普通/合并提交按首个父提交比较；初始提交按空内容比较。
- [x] B06 后台读取 Git 和计算 Diff，忽略切换选择后迟到的结果；为二进制、非 UTF-8、大文件提供提示。
- [x] B07 固定 GPUI 版本和 Cargo.lock；macOS 编译及窗口运行验证；四项 Git/Diff 测试和 Clippy 检查。

后续已通过 W05 补齐暂存与未暂存分组，通过 D03 补齐差异块导航。后续 D01/D02 已补齐文本选择、复制和基础语法高亮；B05 尚不包含旧版的合并提交三栏视图。B06 的虚拟渲染不代表读取、内存和计算性能已完成优化。

## 每项完成的标准

1. 用户能从界面完成该项操作，结果与 Git CLI/磁盘内容一致。
2. 涉及 Git 语义、文本映射、数据写入的改动在临时仓库或固定文本样例中验证；布局与输入交互实际启动窗口检查。
3. 错误、取消、空状态和连续切换不破坏数据或显示旧结果。
4. 相应说明、清单状态和验证记录一起更新；不把部分实现标为整个模块完成。
